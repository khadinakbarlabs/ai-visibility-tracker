# AI Search Visibility Tracker Privacy Notice

Published by Khadin Akbar. Updated 2026-10-05.

AI Search Visibility Tracker is a skills-only plugin maintained by Khadin Akbar. It guides the current host AI assistant to use a user-owned Apify connection, official CLI or secure API integration. It includes no publisher-operated server, database, analytics or automatic telemetry.

## Requested checks

When you authorize research, your selected integration sends the configured domains, page URLs, keywords, questions, competitor domains and run settings to the mapped Apify Actors for AI citations, competitor traffic and rankings, keywords, Google Trends, backlink samples and link discovery. Public result pages may also be inspected to qualify opportunities. Apify executes the run using the Actor's configured services. Answers, citations, diagnostics and run records are returned through Apify. AI, search, traffic, keyword and backlink data providers used by the selected Actors may process the submitted search terms or domains. Use public business information only; do not supply personal, confidential or customer data.

## Credentials

Use an authorized user-owned connection, official local login or secure host API-key setup. The plugin asks for secure connection/key setup only when needed, never tokens in ordinary chat. It does not copy authentication files or publish credentials. The selected host/CLI manages authentication independently. Your assistant and host platform have their own access controls and policies.

## Storage and retention

Research-led onboarding saves private website/market profiles, public research sources, labelled assumptions, competitors, panels, budget approvals, schedule identifiers, visual reports and concise analytical context outside the plugin when host storage is available. Exportable state is provided when persistent storage is unavailable. Your current host LLM performs analysis under its own policies. Optional existing MCP/connector integrations may have their own telemetry and privacy settings. Apify cloud schedules store accepted Actor inputs and timing in your own Apify account. A host recurring agent uses your chosen private state and its own scheduler. Reports are sent to another destination only when you request and authorize that delivery; do not include credentials or confidential inputs in a scheduled prompt. The package supplies no background server or independent reporting service.

Apify stores run inputs, results and records in your account according to its own services and policies. The plugin does not promise a fixed retention period or deletion on Apify's behalf. Local exports remain wherever you and your assistant save them. Your host platform may retain conversation content under its own policies. Manage deletion and retention through each service and remove local exports when they are no longer needed.

The skills package itself adds no publisher storage or tracking. The Apify Actor and any separately hosted service are outside this package; their policies also apply. See [Apify privacy information](https://apify.com/privacy-policy) and your AI host's privacy notice.

## Private feedback and optional integrations

Where host storage is available, campaign records can include business preferences/corrections, hypotheses, recommendation feedback, action status and user-acknowledged implementation dates. Minimal observable activity distinguishes user reviews, Actor runs, generated reports and confirmed delivery. The package has no automatic install, session, retention or report-view telemetry sent to its publisher. Feedback changes saved context/recommendations, not the underlying model's weights.

An existing authorized Search Console tool or a user-supplied analytics export may optionally enrich analysis. This package creates no Google connection or new access scopes. Keep business summaries only; avoid personal/customer data. Each connected service and host retains its own access and privacy policies.

You can ask to inspect/correct/export campaign context or remove preferences/local records. The assistant uses available host/service controls, preserves measurements when correcting preferences, and explains external retention or deletion it cannot verify. Pause associated tracking before deleting state needed by jobs. Deleting campaign files doesn't itself delete Apify records or host conversations.

Product feedback is optional: the assistant can prepare a redacted support draft and share it only with explicit authorization. Domain lists, transcripts, private evidence, account/auth data and run links are omitted by default. Public issues are visible to others. No automatic feedback uploads occur.

## Support

Support issues may be publicly visible. Do not attach credentials, private run data or personal information. Use the [support page](SUPPORT.md) to report a redacted problem. Questions about this notice may also be raised through that support channel.

This notice applies to the skills package. It does not replace the privacy terms of Apify, the Actor runtime, AI providers or your AI assistant host.

## User-owned credentials

Every live user authenticates to their own Apify account through an existing authorized connector/MCP connection, official local `apify login`, or secure host API-key setup. Never use, bundle, borrow or distribute publisher credentials. If ownership is uncertain, have the user verify the account locally before billable work. Existing user-owned access is sufficient; ask for connection or secure key setup only when access is missing. Never solicit tokens in ordinary chat or save them in campaign records. Saved-export analysis needs no token.
