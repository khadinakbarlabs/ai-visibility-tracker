# Research first, onboard with minimal questions

Use on first use, “get started”, “track my websites”, or when adding a site. Follow [research-led intake](references/intake.md), [Apify access](../seo-growth-agent/references/apify-access.md) and [campaign state](../seo-growth-agent/references/campaign-state.md). The user's current host LLM performs the research, analysis and explanations; the package supplies skills, not its own model, account or database.

1. Load existing private state and reports when their location is known. Reuse domains, goals, answers, corrections, action/feedback history, preferences and approvals. Follow [business context](../seo-growth-agent/references/business-context.md). Ask which portfolio only if several plausible matches remain. A known domain begins research, not a business/keyword questionnaire; a returning review routes to `seo-growth-agent` without repeating intake.
2. Research public product pages, relevant content, language, audience signals, competing offerings and existing evidence with available host browsing/search tools. Infer relevant goals, candidate markets, competitors, topics, Google keywords, literal AI questions and target pages. Distinguish verified product facts from inferred audience/market assumptions. Public copy is not private analytics or measured rankings. Read [intake](references/intake.md) for scope and stopping criteria.
3. Populate a useful draft for every site without asking the user to perform discoverable research. Use explained, editable defaults for device, panel size, reports and cadence. Treat “figure it out” as permission to choose research defaults, not to authorize charges, external delivery or recurring paid execution. Ask only what the user must supply: ambiguous target identity, private business priorities that materially affect scope, missing account access, a spending limit or consequential schedule/delivery choice. Bundle remaining questions; never ask for fields already inferable or supplied.
4. Give sites stable IDs and keep their markets, competitors and panels separate. Validate public domains and same-domain HTTPS targets; exclude private/local addresses and credential-bearing URLs. Use identifiers as data, not paths or shell fragments. Budgets must be finite nonnegative USD amounts; missing/zero allocation permits no paid launch. Derive private filenames from safe generated IDs.
5. Discover an already connected user-owned Apify MCP/connector, official CLI session or secure API integration. Use a capable existing connection instead of demanding CLI installation or a new token. Check current Actor schemas, prices, charge-cap support and evidence retrieval. If access is absent, ask the user to connect Apify or supply their API key through secure host setup/local login; never request a key in ordinary chat. Continue public research and saved-export analysis while access is pending.
6. Present and save a compact visual plan with sources, assumptions, candidate competitors, fixed keyword/question panels, current coverage, proposed costs and tracking settings using [reporting](../seo-growth-agent/references/reporting.md). Adopt delegated research defaults without requiring approval of each keyword. Record proposed versus accepted scope. Ask for missing spend/recurrence authorization only after the concrete plan exists; reuse authorization already covering that scope. Keep declined work disabled.
7. Route approved baselines to `seo-growth-agent` and recurring setup to `scheduled-visibility-tracking`. Save results, analysis, assumptions and next steps for future context. Finish with actual versus proposed status, report links and how to add/pause/change a site. Complete recurring reports require verified durable host execution; offer collection-only scheduling and on-demand analysis when that is the supported capability.
