# Feedback, actions and returning reviews

Private campaign context improves future recommendations, not model weights or shared plugin instructions. Offer feedback only when useful: useful, already done, wrong audience, too much effort, incorrect/outdated, or a free-text correction. Don't survey every response.

Record feedback ID, website/market scope, action/claim ID, timestamp, user-stated reason and resulting decision. Avoid transcripts/personal data. Corrections update scoped context; effort feedback changes feasible work; rejected actions stay suppressed unless new evidence or an explicit request warrants reconsideration. Record that reason before resurfacing an action.

States: proposed → accepted → in progress → completed, with deferred/rejected alternatives. “Already done” or “I completed this” can acknowledge implementation; save the reported date or mark unknown instead of inventing an earlier date. Verification is user acknowledged or independently observed. A brief, draft, scheduler run or silent user isn't completion. Retain evidence, target page, effort/confidence, reason, follow-up panel/due date. Avoid duplicate actions for unresolved work.

Returning requests:

- **What changed?** Compare matching evidence/coverage; without new data state the latest observation date.
- **What should I do this week?** Use goals, feasible effort and open work; select at most three priorities with evidence/concrete steps.
- **Make a brief / explain this.** Draft or explain; preserve implementation status and publishing boundaries.
- **I completed this.** Log acknowledgement, preserve prior evidence, plan a suitable matching follow-up. Launch only with valid scope/cost approval.
- **Pause this website.** Route to scheduling, persist pause and verify jobs; don't delete history.

## Private activity, not publisher analytics

Where observable save minimal event ID, timestamp, scope, type and related action/report/execution ID. Types: user review, explicit usefulness feedback, acknowledged implementation, Actor run, generated report, confirmed delivery. Deduplicate IDs. Sessions require reliable host session/conversation identifiers; otherwise count explicit review events and mark sessions unavailable. Scheduler runs aren't human sessions; delivery isn't reading; recommendations aren't implementation.

Summaries may show observed time to first substantive report, explicit usefulness ratings, acknowledged completion, review events, failures and recorded spend. Explain denominators/missing events. Spend per useful finding requires explicit useful-finding feedback linked to charges; otherwise unavailable. No install, cross-user retention, report-view or revenue analytics exist in this package. Aim for useful decisions/completed work, not extra chat turns or run volume.

## Optional product feedback

If requested, prepare a redacted draft: plugin version, host, workflow, expected/actual behavior and user-approved non-sensitive examples. Omit domain lists, transcripts, private evidence, account/auth data and run links by default. Show destination/exact text; send/post only with explicit authorization, otherwise leave a draft. Existing support channels apply; no automatic upload, issue creation or telemetry. Publisher improvements use reviewed releases, not individual-user self-modification.
